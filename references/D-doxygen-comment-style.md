# Doxygen 注释规约 — §1–§6

# 本规约是 C 编码风格 §11 的"外部权威"，C 编码风格 SKILL.md 的 D-01 ~ D-10 引用本文件。

# 硬规则快速索引（详见各章节）：
# - D-01 [CRITICAL] .h API：中文 @brief + @param[in|out] + @return（非 void）；禁 @details
# - D-02 [HIGH]     .c API：同 .h，可选 @details / @note / @warning / @see
# - D-03 [HIGH]     static helpers：至少一行 @brief
# - D-04 [HIGH]     注释字符规则（//、/* */、/** */ 分工）
# - D-05 [CRITICAL] void 函数必须省略 @return
# - D-06 [HIGH]     同一函数只允许一个 @return
# - D-07 [HIGH]     @param 顺序与形参声明顺序一致
# - D-08 [MEDIUM]   注释中文为主，技术名词 / API/文件名 / 寄存器名保留英文
# - D-09 [MEDIUM]   中文 @brief 用全角标点；返回值说明用半角冒号
# - D-10 [MEDIUM]   TODO / FIXME 必须带负责人与日期

## §1 适用范围

| 注释对象 | 是否需要 | 说明 |
|----------|----------|------|
| 头文件 `.h` 中声明的公开 API | ✅ **必须**完整注释 | 别人会调用 |
| `.c` 中非 `static` 函数 | ✅ **必须**完整注释 | 跨文件可见 |
| `.c` 中 `static` 函数 | ⚠️ **必须** `@brief`（1 行即可） | 内部 helper |
| 公共变量 / 模块状态 | ⚠️ **按需**简要注释 | 名称不足以表达含义时 |
| 结构体成员 | ⚠️ **按需**简要注释 | 使用紧邻声明的中文 `//` |
| 厂商 SDK / 第三方代码 | ❌ 不加 | 不在维护范围 |

## §2 标准模板（**严格遵守**）

### §2.1 `.c` 文件模板

- `.h` 文件**禁止使用 `@details`**
- `.c` 文件按需使用 `@details`：复杂函数（多步骤、有副作用、有状态依赖或实现超过 5 行）推荐补充；简单函数可省略
- 必须有中文 `@brief`（一句）
- 参数按形参顺序逐行写 `@param[in]` / `@param[out]` / `@param[in,out]`；无参不写
- 非 void 返回按需使用 `@return` 标签说明返回值
- `@note` / `@warning` / `@see` 可选
- 所有注释原则上使用中文；技术名词、API、文件名和寄存器名保留英文

### §2.2 `.h` 文件模板

- 公开 API 注释与 `.c` 一致，但**禁止使用 `@details`**
- 公开 API 的契约通过 `@brief`、`@param`、`@return` 表达，不在头文件中描述实现过程

### §2.3 强制约束

- `//`（行内 / 单行注释）—— 默认首选；一行一句
- `/* ... */`（多行 / 块注释）—— 多行注释、函数实现说明、临时屏蔽代码、版权头
- `/** ... */`（文档注释）—— Doxygen 工具识别；普通解释不要混用
- `@brief` 必须使用中文，可分多行
- 中文 `@brief` 用全角标点（`，。：；`），句末加句号
- `@param` 只写适用方向：`[in]` / `[out]` / `[in,out]`，以及参数含义；无参不写
- `@param` 顺序与函数形参顺序一致
- `@return` 与函数返回类型对齐；void 函数**必须省略** `@return`
- 每个函数只使用一个 `@return` 标签；返回值与说明使用半角冒号和空格分隔
- `@details`：`.c` 函数按需补充；`.h` 函数禁止使用
- `@note` / `@warning` / `@see` 可选
- 注释主体以中文为主，技术名词与标识符保留英文

### §2.4 行宽

- 当单行字符过多时，进行换行避免需要频繁拉动编辑器横轴阅读代码
- 中文字符时每行 < 120 字符；中文字符时每行 < 180 字符；混合时 < 150 字符（保持 diff 可读）
- `@return` 超宽时允许换行，续行与第一项返回值说明对齐
- `@brief` / `@details` 可分多行，续行缩进 4 个空格

## §3 补充实例

| 小节 | 主题 |
|---|---|
| §3.1 | 无返回值（void）函数：`@note`/`@param` 而**不写** `@return` |
| §3.2 | 无参数函数：`/** @brief   xxx    */` 单行 |
| §3.3 | 内部 `static` 函数：至少 1 行 `@brief` |

## §4 头文件 vs .c 文件

| 位置 | 注释放在哪 |
|------|-----------|
| 函数声明（`X.h`） | **禁止** Doxygen 注释包含 `@details` |
| 函数实现（`X.c`） | **必须** Doxygen 注释包含 `@brief` |

- `.h` 与 `.c` 的 API 契约必须保持一致
- 实现特有的副作用或状态依赖写在 `.c` 的 `@details` 或 `@note` 或 `@warning` 中

## §5 变量、状态机状态与结构体成员

- 公共变量、模块状态和结构体成员在名称不足以表达实际含义时，必须添加简明中文注释
- 状态枚举值、状态宏或状态变量名称不足以表达含义时，使用中文说明状态含义
- 状态切换的触发条件或副作用不明显时，使用中文说明切换原因
- 注释只说明必要信息，包括实际含义、单位或范围、特殊值，以及必要的生命周期或 ISR / 任务归属
- 计数器与诊断字段必须说明统计单位、累计边界，以及是否包含丢弃或待处理数据
- 结构体成员使用紧邻声明的中文；行尾注释导致超宽时，将放在声明上一行
- 函数中的结构体参数，`@param` 应说明输入输出方向

## §6 手工自查清单

提交前自查：

- 每个 `.h` 中的函数都有必要的注释
- 每个 `.c` 中的非 static 函数都有必要的注释
- 每个函数都**有中文 `@brief`**
- `.c` 函数按需使用中文 `@details`，`.h` 函数禁止使用
- `@param` 只在有参数时写，并标注 `[in] / [out] / [in,out]`
- 非 void 函数只使用一个 `@return`
- 必要的公共变量、模块状态和结构体成员使用简明中文
- 必要的状态含义与切换原因使用简明中文
- 函数中的结构体参数通过 `@param` 说明输入输出方向和参数含义
